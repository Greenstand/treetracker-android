# Deleting a user in Settings leaves the deleted user as the current user (#1448)

## What happens

Settings → Delete account uses `UserSelectViewModel`. When you pick a user, `DeleteProfileScreen` sends `UserSelectAction.SelectUser` for them. `SelectUser` makes that user the **current user**: it calls `prefs.setUserId(user.id)`, which keys every `UserPrefKey`, and sets `CaptureSetupScopeManager.getData().user`. Confirming the delete sends `UserSelectAction.DeleteUser`, which removes the user's row but resets neither value. After a successful delete, the app's current user id and the capture-setup user both still point at a user who no longer exists.

## Steps to reproduce

1. Sign up an admin, then add a second user (Bob).
2. Settings → Delete account → pick Bob → forward arrow → confirm.
3. Bob is deleted, but `Preferences` still holds Bob's id as the current user id, and `CaptureSetupData.user` is still Bob.

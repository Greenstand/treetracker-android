# Double tap on Next skips org-configured setup steps (session note, wallet select, add wallet) (#1442)

## What happens

Next on user select and Add org is guarded against double taps with `navigation/DoubleTapGuard.kt`. The setup steps an org can add to its capture setup flow (session note, wallet select, add wallet) still call `CaptureSetupNavigationController.navForward` directly from Next.

Every setup screen's Next is the bottom bar's right arrow. So the second tap of a double tap on one screen's Next lands on the next screen's Next. That tap comes from a new screen that is already on top, so it gets past both the origin throttle in `Navigator` and `navForward`'s same-screen guard. Setup then moves on a second step.

- **Session note:** its Next is always enabled. For an org whose setup flow is `[user-select, session-note]`, a double tap on user select's Next skips the session note, starts the session and opens capture.
- **Wallet select / add wallet:** their Next is disabled until a wallet is picked or a name is typed. They are lower risk, but the second tap goes through the same way once their Next is live.

## Steps to reproduce

1. Seed an org with a session note step: `bash e2e/seed-org.sh -s <serial> session-note`.
2. Open the app, tap Track and pick a user.
3. Double tap Next on user select.

Expected: the session note screen opens and stays open.
Actual: the session note is skipped and capture opens (on CI's 320x640 layout the second tap lands on the session note's Next).
